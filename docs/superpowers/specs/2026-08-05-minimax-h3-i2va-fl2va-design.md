# MiniMax H3 I2VA 与 FL2VA 接入设计

## 目标

将用户已在 ComfyUI 实机运行成功的 `MiniMax视频适配版.json` 拆分后接入 OpenDrama，第一期只提供两种 MiniMax H3 本地视频能力：

- I2VA：首帧图生联合音视频。
- FL2VA：首帧到尾帧的联合音视频。

工作流中的 Codex 调用必须移到 OpenDrama，复用项目统一的 Codex 文本与多图视觉能力。ComfyUI 工作流只负责 H3 推理，不再负责提示词规划、模式判断或业务图片角色判断。

## 已确认的产品边界

- 第一阶段只实现 I2VA 和 FL2VA。
- 暂不实现 T2VA、L2VA、Ref2VA 或中间指导帧。
- I2VA 与 FL2VA 使用两个独立的纯 H3 工作流，不在运行时动态增删关键帧连接。
- 复用现有普通图生视频和首尾帧业务入口，不新增第三套视频生成交互。
- H3 原始视频保留联合生成的音轨。
- 第一阶段 H3 提示词默认禁止人物对白，允许动作音、环境声和必要的非剧情内配乐。
- 后续配音和环境音阶段决定是否混音、降低或替换 H3 原声；本功能不修改现有音频合成链路。
- H3 失败时不自动降级到 LTX 或其他视频模型，也不在 FL2VA 失败后偷偷改用 I2VA。

## 来源工作流结论

来源文件：`/Users/tigli/workspace/workspace/MiniMax视频适配版.json`。

该文件为 ComfyUI UI 工作流，包含 41 个节点、44 条连线和 6 个分组，节点 ID 与连线结构完整。核心链路是：

1. 首帧、尾帧和基础动作描述进入 `RH_CODEX_NODE`。
2. Codex 输出 MiniMax H3 英文多模态提示词。
3. `MiniMaxH3ImageToVideo` 生成视频与音频联合 latent。
4. `BasicGuider`、`BasicScheduler` 与 `SamplerCustomAdvanced` 使用 20 步、`res_multistep`、`simple`、denoise=1 完成采样。
5. 视频 VAE 和音频 VAE 分别解码画面与声音。
6. `CreateVideo` 以 24 FPS、8 bit 合成，`SaveVideo` 输出 H.264 视频。

来源工作流还包含 `PathchSageAttentionKJ`、`EasyCache` 和 `VRAM_Debug`，用于注意力优化、采样缓存和显存清理。第一阶段保留用户已经跑通的这些节点与参数，但不把它们暴露为产品级用户选项。

原工作流不能原样注册到 OpenDrama：

- `RH_CODEX_NODE` 固定到 Windows 本机 Codex 路径和模型，不能作为可移植项目契约。
- 中间参考帧当前只完成加载与缩放，并没有接入 Codex 或 H3。
- 项目通用图片注入器按 `LoadImage` 节点 ID 排序，三张图会把中间帧误注入 H3 尾帧槽位，真正尾帧随后成为不可达节点。
- 通用时长启发式不能修改连接在 `ComfyMathExpression` 上游的 `PrimitiveFloat`，请求时长会继续使用工作流保存的 10 秒。
- 通用尺寸启发式只能改变比例，不能可靠锁定 H3 画布尺寸和像素预算。

因此，项目必须为 H3 建立明确的提示词、图片、时间和输出契约，不能依赖通用节点猜测。

## 方案选择

### 采用方案

采用“两个纯 H3 工作流 + 一个 H3 专用适配器 + 一个项目侧 H3 提示词规划器”：

- `h3-i2va`：只连接首帧。
- `h3-fl2va`：同时连接首帧和尾帧。
- `H3PromptPlanner`：使用项目统一 Codex 能力生成 H3 提示词。
- `H3WorkflowAdapter`：根据确定模式注入提示词、图片、时长、尺寸和种子。

两个工作流共享模型、VAE、采样器、帧数计算、画布约束、输出和持久化逻辑，但保持独立的图片连接契约。

### 未采用方案

- 单个动态工作流：文件较少，但需要运行时增删首尾帧连接，容易重现图片错位和隐式模式切换问题。
- 将 Codex 和 H3 拆成两个独立队列任务：扩展性更强，但第一阶段增加了队列状态、恢复和用户交互复杂度。第一阶段在同一个视频任务中采用可恢复的两个执行阶段即可。

## 总体架构

```text
项目分镜与视频生成请求
  -> H3 模式与媒体归属校验
  -> H3PromptPlanner（项目统一 Codex，多图视觉）
  -> 保存 H3 最终提示词到任务上下文
  -> H3WorkflowAdapter（确定性参数与图片注入）
     |- h3-i2va：首帧 + H3 提示词
     `- h3-fl2va：首帧 + 尾帧 + H3 提示词
  -> ComfyUI H3 联合音视频生成
  -> 现有视频媒体流式持久化
```

项目代码决定模式、图片角色、时长和工作流。Codex 只负责把确定的业务上下文与视觉差异转换为 H3 可执行提示词，不能决定使用哪个工作流，也不能改变图片编号或把中间图片误声明为 H3 原生关键帧。

## 业务入口映射

- `generationMode=normal` 固定映射到 H3 I2VA。
- `generationMode=firstlastframe` 固定映射到 H3 FL2VA。
- 不认识的模式明确拒绝。
- 工作流选择在服务端完成，客户端不能通过任意 workflow key 绕过模式契约。

I2VA 请求必须正好有一张首帧。FL2VA 请求必须同时具有首帧和尾帧。缺少必需图片时，在调用 Codex 或上传 ComfyUI 之前失败。

## H3 提示词规划器

### 输入

`H3PromptPlanner` 接收由项目代码组装的确定性上下文：

```ts
type H3PromptPlannerInput = {
  mode: 'i2va' | 'fl2va'
  creatorPrompt: string
  continuityPrompt: string
  durationSeconds: number
  firstFrameUrl: string
  lastFrameUrl?: string
}
```

- I2VA 只向 Codex 传首帧。
- FL2VA 严格按首帧、尾帧顺序传两张图。
- Codex 用户消息必须显式声明图片角色，不允许根据附件数量猜测。
- 现有分镜连续性提示继续提供当前动作、人物、场景、镜头、前后镜上下文和目标时长。

### 输出

Codex 只返回最终可提交给 H3 的英文提示词。模式、图片绑定、工作流 key、尺寸和时长由项目代码持有，不从模型输出反向推断。

提示词必须包含且各出现一次：

- `integrated_multimodal_description`
- `overall_soundscape`
- `non_diegetic_music`

I2VA 提示词应声明 Picture 1 在起始时间对齐。FL2VA 提示词应声明 Picture 1 为首帧、Picture 2 为尾帧，并给出与目标时长一致的终点。第一阶段提示词不得包含 H3 对白标记 `<d>`，防止与项目独立配音重复。

服务端验证输出非空、字段完整、模式对应的图片编号正确且没有对白标记。格式不合格时只允许一次带原始结果的修复请求；仍不合格则任务失败，不使用通用提示词伪装成功。

### 可恢复性

生成成功的 H3 提示词保存到当前视频任务上下文。ComfyUI 提交失败或用户针对同一输入重试时，复用已经验证的提示词，避免再次调用 Codex 得到不同运动路径。任何影响语义的输入发生变化后，旧提示词指纹失效并重新规划，包括：

- 模式；
- 首帧或尾帧媒体身份；
- 创作者提示词或连续性提示；
- 目标时长。

## H3 工作流契约

### I2VA

- 使用 FL2VA 系列 H3 模型的 I2VA 能力。
- 只存在首帧加载与 `first_frame` 连接。
- 最终 ComfyUI API 图不能包含 `last_frame` 输入。
- H3 与 Codex 都只接收首帧。

### FL2VA

- 同时存在首帧与尾帧加载节点。
- `first_frame` 和 `last_frame` 使用固定节点 ID 或显式参数契约注入，禁止按 `LoadImage` 排序猜测。
- H3 与 Codex 接收相同的首尾帧语义顺序。
- 缺少任意关键帧时拒绝提交。

### 共享参数

- FPS 固定为 24，不向用户开放其他值。
- 产品时长限定为 5 至 15 秒。
- 请求秒数先换算为 `round(seconds * 24)`，再向上对齐至 MiniMax H3 的 `17k+5` 帧网格。
- 视频提示词的终点时间使用用户请求时长；媒体验收接受帧网格导致的轻微超长。
- 宽高必须为正数并按 32 对齐，最终像素数不得超过 `768 * 1344`。
- 请求同时提供宽高且超过像素预算时，按原比例整体缩小，再将两轴就近对齐到 32；若对齐后重新超过预算，则以 32 为步长缩小较长轴直到满足预算，不能单独裁掉或非等比压缩某一轴。
- 未指定尺寸时，以首帧比例为几何基准：先把短边设为 768，超过 `768 * 1344` 时按比例整体缩小，最后应用同一套 32 对齐和预算收敛规则。FL2VA 同样以首帧而不是尾帧决定画布。
- 首帧和尾帧都使用保持宽高比的 cover 缩放与居中裁切进入最终画布，不能对首帧拉伸而只对尾帧裁切。Codex 视觉提示明确告知最终画布比例，避免把必然被裁掉的边缘内容写成关键动作。
- 采样保持用户已验证配置：20 步、`res_multistep`、`simple`、denoise=1。
- 随机种子由项目生成或复用，不接受非法负数或超出安全整数范围的值。
- 输出固定进入 `CreateVideo` 与 `SaveVideo`，保留视频和音频联合结果。

## 音频策略

H3 输出的原始音轨随视频一起保存，不静音、不剥离。第一阶段的 H3 提示词允许：

- 与动作同步的脚步、碰撞、布料和环境事件音；
- 连续环境底声；
- 必要的非剧情内背景音乐。

第一阶段默认禁止人物对白、旁白、演唱和剧情内可听音乐，避免与项目的配音和环境音工具重复。现有后处理链路可以在未来明确选择保留、衰减、混合或替换 H3 原声，本设计不改变其现有行为。

## 任务与持久化

H3 提示词规划和 ComfyUI 生成属于同一个现有视频生成任务的两个阶段，不新增数据库表或新的顶层队列任务类型。

任务按以下顺序执行：

1. 校验用户、项目、分镜和图片归属。
2. 规范化模式与 H3 参数。
3. 生成或复用 H3 提示词。
4. 解析并预检对应 H3 工作流。
5. 上传所需图片并按语义注入。
6. 提交 ComfyUI 并等待 history 中的终态输出。
7. 沿用现有远程媒体流校验与对象存储持久化。
8. 只有上传完成且任务仍有效时，才更新面板视频结果。

重试与恢复必须保留模式、输入媒体身份、参数、提示词及其指纹，不能只保存最终 ComfyUI prompt ID。

## 错误处理

- 首帧缺失、FL2VA 尾帧缺失或媒体越权：Codex 调用前失败。
- Codex 未配置、执行失败或输出无效：返回明确 H3 提示词规划错误，不提交 ComfyUI。
- 工作流缺失、节点类型漂移、模型节点不符合契约或输出节点不存在：预检失败。
- 时长、FPS、尺寸或种子非法：参数规范化阶段失败。
- I2VA API 图仍存在尾帧，或 FL2VA 首尾帧未注入固定槽位：预检失败。
- ComfyUI 排队、执行、history 或 view 失败：沿用现有明确错误，不改变模式重试。
- 视频没有有效 MIME 或内容长度：媒体持久化失败，不覆盖已有面板视频。
- 不生成占位视频、静音空文件或通用提示词来伪装成功。

## 安全与配置

- 工作流文件不保存 Codex 可执行路径、API key、Cookie、Token 或其他凭据。
- Codex 使用项目现有用户模型配置和可执行文件解析能力。
- ComfyUI 使用现有用户 provider 配置。
- 日志可以记录模式、工作流 key、帧数、尺寸和提示词指纹，但不记录凭据。
- 图片上传、任务读取和媒体结果继续执行用户归属检查。

## 自动化测试

### 提示词规划

- I2VA 只向 Codex 传首帧。
- FL2VA 按首帧、尾帧顺序传两张图，并在提示中固定图片角色。
- 三个 H3 字段均存在且各出现一次。
- 默认输出不含 `<d>` 对白标记。
- 无效输出只修复一次。
- 相同输入重试复用提示词；语义输入变化使提示词失效。

### 工作流适配

- `normal` 只路由到 I2VA，`firstlastframe` 只路由到 FL2VA。
- I2VA 最终 API 图没有 `last_frame`。
- FL2VA 首尾图片进入各自固定输入。
- 5、10、15 秒正确对齐到 `17k+5`。
- 小于 5 秒、超过 15 秒、非 24 FPS、非法尺寸和非法种子被拒绝。
- 提示词、尺寸、帧数、种子、采样器和最终输出节点可以精确断言。
- 解析后的执行图不再包含 `RH_CODEX_NODE`、展示节点、无效中间帧节点或停用的动态切换支路。

### 项目回归

- 现有 LTX 2.3 工作流注册与路由不变。
- 普通视频和首尾帧现有业务请求结构保持兼容。
- 视频任务失败、取消、恢复和流式媒体持久化逻辑保持有效。
- Stable Audio、独立配音和环境音工作流不受影响。
- H3 不成为其他 ComfyUI 工作流的隐式回退目标。

## ComfyUI 实机验收

分别执行一次最小 I2VA 和 FL2VA，必须等待终态：

- 检查 ComfyUI history 中实际工作流、输入图片、最终提示词、尺寸和帧数。
- 使用 FFprobe 确认 H.264 视频流、24 FPS 和音频流存在。
- 校验实际时长符合对齐后的帧数，允许略高于请求秒数。
- 提取首帧和尾帧：I2VA 从输入首帧自然发展；FL2VA 从首帧开始并向尾帧状态收敛。
- 人工检查人物身份、服装、场景、动作连续性，以及动作音和环境声的基本同步。
- 检查 H3 没有生成默认人物对白。

只有两种模式都产生真实成功视频，相关自动化测试、类型检查和工作流结构校验全部通过，才可以宣称完整交付。如果 ComfyUI 或模型不可用，只能报告“静态集成通过、实机生成未验证”。

## 非目标

- 不接入 T2VA、L2VA、Ref2VA 或中间指导帧。
- 不提供 H3 人物对白生成。
- 不重做视频阶段 UI 或首尾帧选择交互。
- 不自动混音、静音或替换 H3 原声。
- 不把 SageAttention、EasyCache、采样器或 FPS 暴露为用户参数。
- 不修改现有 LTX 2.3、Stable Audio、配音或环境音业务语义。
- 不新增数据库表或独立 H3 顶层任务类型。
